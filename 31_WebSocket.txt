--> Problem, Assume you are a server and we have 2 client. Let's say we want to make a chatting appliaction(real Time appliaction) 

|                                           Server
|       Client_1                                                           Client_2
|->NOW,
|   Client 1 want send a message to client 2
|   So, Client_1 sent message to server , Server got message

|                                      ++++++++++++++++++++++++

--> To send message to Client_2 we have two ways : 1) POLLING                2) WebSocket 
|           
|      ~ WAY 1 (POLLING): 
|           Client_2 --> Request message from Server (at regular intervals) --> Server
|           Server --> Check for message --> No message --> Send "No message" to Client_2
|           Client_1-->Send message to --> Server
|           Server --> Check for message --> Message exists --> Send message to Client_2
|           Client_2 --> Request message from Server (at regular intervals) --> Server
|           Server --> Check for message --> No message --> Send "No message" to Client_2
|           Client_1-->Send message to --> Server
|           Server --> Check for message --> Message exists --> Send message to Client_2
|           ...
|           (Repeated for every interval)
|
|
|                       
|           
|   SUMMARY:- Client_2 asking server after each interval whether there is message for me or not. If yes server send 
|             message else send no message. This method overkilling as if there are many users then there will me 
|             very much load on server
|
|       Polling: Sending Message to Client_2

|      ~ WAY 2 (WebSocket): More efficient. 
|               
|             Client_1 --> Send message to Server --> Server sees it's for Client_2 --> Sends message to Client_2
|             Client_2 --> Send message to Server --> Server sees it's for Client_1 --> Sends message to Client_1
|             (Bi-directional communication)
|             Client_1 or Client_2 --> Want to leave the room --> Can close the connection
|       

WebSocket: Real-Time Messaging Let's say we have a Client and Server

BY ARROWS:-
|       Client --> HTTP Request to make WebSocket(Permanent) connection (using upgrade header) --> Server
|       Server <-- Accept Request --> Client
|       Server --> Send response to Client (OK)
|       WebSocket Connection remains open (doesn't close)
|       Server --> Send message to Client
|       Server --> Send message to Client
|       Server --> Send message to Client
|       Client --> Send message to Server (doesn't wait for server's response)
|       Server --> Send message to Client
|       Client --> Send message to Server (doesn't wait for server's response)
|       Client --> Send message to Server (doesn't wait for server's response)
|       Bi-directional communication established
|       Connection stays open for continuous communication
|       If Client wants to leave, they can close the connection
|       Once closed, Server can't send any message to Client

BY DIAGRAM:-
|               +---------+           +---------+
|               |  Client |           |  Server |
|               +---------+           +---------+
|                    |                     |
|                    |  HTTP Request       |
|                    +-------------------->|
|                    |                     |
|                    |   Response (OK)     |
|                    <---------------------+
|                    |                     |
|                    |  WebSocket Upgrade  |
|                    +-------------------->|
|                    |                     |
|                    |  Persistent         |
|                    |  Connection         |
|                    |                     |
|                    |  Bi-Directional     |
|                    |  Communication      |
|                    |                     |
|               +---------+           +---------+
|               |  Client |           |  Server |
|               +---------+           +---------+
|                    |                     |
|                    |  Send Message       |
|                    +-------------------->|
|                    |                     |
|                    |   Send Response     |
|                    <---------------------+
|                    |                     |
|                    |  Keep Connection    |
|                    |  Open               |
|                    |                     |
|                    |   (Close Connection)|
|                    +-------------------->|
|
|   SUMMARY:- The client sends an HTTP request to the server to upgrade the connection to WebSocket. Once accepted, 
|             a persistent, bi-directional communication is established between the client and server. This allows 
|             real-time messaging without the need to repeatedly open new connections.
|

---> How to make WebSocket?
|   
|   - To make WebSocket, 
|                       We initiallly send HTTP Request we tell in it's Headers that we want to Upgrade it to 
|                       WebSocket Server handle this Request and establish WebSocket connection for us. 

---> Upgrade, The HTTP Upgrade request and response header can be used to upgrade an already-established 
|             client/server connection to a different protocol (over the same transport protocol). For example,
|             it can be used by a client to upgrade a connection from HTTP/1.1 to HTTP/2, or an HTTP(S) connection 
|             to a WebSocket connection.

---> For More About, Upgrade              -> https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Upgrade
|                    Upgrade to WebSocket -> https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Upgrade#upgrading_to_websocket
